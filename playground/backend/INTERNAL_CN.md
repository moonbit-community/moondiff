# Playground 后端设计说明

## 认证与会话生命周期

后端负责 Cookie 和 CSRF 校验，并通过
[GitHub App Device Flow](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app#using-the-device-flow-to-generate-a-user-access-token-for-a-github-app)
完成用户授权。
向 GitHub 请求设备代码时使用 Client ID；轮询令牌时使用相同的 ID、设备代码和设备授权类型。
此流程无需浏览器回调或客户端密钥。刷新令牌时仅需提供 Client ID、
刷新令牌和刷新授权类型。共享的刷新请求会在事务中持久化轮换后的令牌对。

后端在首次网络操作前预留授权记录。
SQLite 保存对应的会话、授权标识符、状态版本、阶段、加密凭据、公开验证码、验证 URL、
过期时间、轮询间隔、下次执行时间和重试退避状态。部分唯一索引确保每个会话最多只有一个正在进行的授权。
并发的发起请求通过别名记录复用同一授权。取消的登录尝试会保留到过期，
包括在发起请求到达前就已取消的尝试；迟到的请求无法重新创建已取消的尝试。
每次尝试最长持续 15 分钟，GitHub 可以缩短该期限。
当前的待授权数据格式不兼容旧令牌，也不提供迁移。

每个授权的待完成操作共享一个异步任务。执行时间以毫秒持久化，
返回给浏览器的等待时间向上取整为秒，因此亚秒级取整不会违反 GitHub 的轮询间隔要求。
每次收到降低轮询频率的响应，都会将轮询间隔至少再延长 5 秒。
临时网络故障、5xx 错误和限流会触发退避重试，并遵守响应头中以秒数表示的重试等待时间。
限流和临时故障状态在重启后仍然保留。
授权被拒绝、过期、设备代码无效或配置错误会结束当前尝试，并清除其加密凭据。

设备代码兑换成令牌后，在查询用户身份之前，先保存加密的令牌响应及签发时间，并进入身份验证阶段。
身份查询出现临时故障时，可以在重启后继续处理，无需再次兑换设备代码，也不会延长令牌有效期。
只有通过身份验证后，令牌才能写入会话。写入会话令牌与完成授权在同一事务中执行，
并更新会话状态版本，防止旧的刷新结果覆盖新登录。取消授权和退出登录也会使正在进行的操作失效。
设备授权任务与刷新任务一样，不会因某个等待结果的 HTTP 请求被取消而终止。

浏览器负责显示验证码，并且只在用户点击后打开 GitHub 验证页面。
生产环境仅接受 GitHub 官方的设备验证页面；测试模式仅接受配置的回环 OAuth 源地址下的
设备验证页面。前端 MoonBit `github_client` 管理 CSRF、请求代次、认证版本和状态请求序号；最多调度一个轮询，同时检查请求标识符和自身的认证状态版本，
并在取消、退出登录或页面卸载时清除定时器和请求。
常规的变更页面导航会保留认证进度。初始化和页面重新激活时会恢复服务端会话，
包括尚未过期的待完成登录验证码。

凭据失效或过期后仍保留账户 ID，因此重新登录同一账户时可以保留草稿。
切换账户会清除上一账户的数据和草稿。会话在 30 天后过期。
浏览器中唯一的凭据是随机生成、带有 HttpOnly 和 SameSite=Lax 属性的 Cookie；
HTTPS 下使用带有 Secure 属性且仅限当前主机的 Cookie。
SQLite 保存该 Cookie 的 SHA-256 摘要、GitHub 用户 ID、CSRF 令牌和加密的 GitHub 令牌对。
写操作要求请求来源与配置的公开访问地址一致，并提供会话 CSRF 令牌。
退出登录会删除会话和待完成的授权；迟到的设备请求和刷新请求无法重新创建该会话。
后端不会从代理请求头推断源地址。

## 令牌加密与比较

令牌加密封装采用 AES-256-CBC 和 PKCS#7 填充，
每次加密都会生成新的 16 字节 IV。64 字节密钥拆分为两个独立的 32 字节密钥，
分别用于加密和 HMAC。HMAC-SHA256 校验封装版本、会话摘要、GitHub 用户 ID、IV 和密文。
待完成设备授权的加密封装使用带有设备授权标记的授权标识符代替用户 ID，
将凭据同时绑定到会话和授权。在解密或移除填充前，先通过恒定时间比较验证 HMAC。
持久化的密钥校验值会阻止使用不同密钥启动服务。

HMAC 和 CSRF 均采用相同的恒定时间比较方式。
长度相同时，会遍历所有字节并汇总差异，最后统一判断是否相等。
长度不同时会立即返回，因为长度信息本身是公开的。
更换编译器或执行目标时，需要重新确认比较过程的实际耗时特性；
仅凭设计和功能测试，无法保证运行时仍具有恒定时间特性。

## SQLite 与进程独占

SQLite 负责持久化会话和待完成的授权。
Wasm 的 SQLite 宿主接口不支持数据库参数调优。新数据库使用 SQLite 的默认日志模式，
已有的 WAL 数据库保留原有模式。触发器负责约束授权与会话的归属关系并执行级联删除，
不依赖连接是否启用外键检查。Native 构建会显式启用 WAL 和外键，
并设置 5 秒的繁忙等待超时。

后端创建的数据库仅允许所有者读写，并持有数据库锁，
防止多个实例同时运行，升级期间也不例外。两种目标都使用这一单进程锁。
运行要求和备份步骤见[会话与备份](../README_CN.md#会话与备份)。

## GitHub 请求与静态资源

后端限制允许的 GitHub 操作和参数。
未知操作和额外参数会被拒绝；删除操作会检查评论作者的 GitHub 用户 ID。
服务端不接受任意上游 URL，发送请求时也不会跟随重定向。
响应、请求和分页限制见 [HTTP 接口约定](../README_CN.md#http-接口约定)。

后端提供静态资源，并为有效的变更路由提供应用入口。
它会拒绝路径穿越以及指向静态资源根目录之外的符号链接。
数据库和监听器初始化完成后，健康检查接口才可用。

## 回归测试

- 加密测试：令牌加密封装、填充和比较。
- 共享协议测试：所有请求和响应往返、严格参数校验、大整数和源码解码，在 JS、Wasm、Wasm GC 和 Native 执行。
- 后端集成测试：在 Wasm 运行环境中执行，
  使用临时 SQLite 数据库和本地 GitHub/OAuth 模拟服务。覆盖已有 WAL 数据库、
  无需客户端密钥的登录和刷新、共享轮询、延长轮询间隔、取消、过期、拒绝授权、临时故障恢复和重启。
- 浏览器认证测试：在 Chromium 中测试真实的 Wasm
  设备登录流程，包括复制验证码、用户主动验证、刷新页面、取消和延迟响应。
  其他前端浏览器测试使用同源 RPC 模拟数据覆盖审阅功能回归。
- MoonBit 传输层测试：注入可控网络和定时器，验证状态版本、标识符、并发轮询、取消、迟到成功或失败、丢失 start 响应、规范 ID 恢复和页面卸载。

运行这些测试的命令见[检查与测试](../README_CN.md#检查与测试)。
