# 顶层声明匹配原理

[English version](./INTERNAL.md)

顶层匹配用于判断旧源文件中的声明与新源文件中的哪些声明相对应。它发生在声明内部的细粒度 diff 之前，因此会直接影响一项变化最终被呈现为既有声明的修改、删除、插入，还是移动。

这套策略有意保持保守。错误配对会把两个无关声明之间的大改写伪装成一次小修改，这通常比显示删除和插入更具误导性。因此，面对歧义时，匹配器宁愿漏掉一个看似合理的对应关系，也不接受证据不足的配对。

## 基本模型

源文件被视为一组有顺序的声明单元。一个单元包含一个顶层声明，以及归属于它的前置内容，例如文档和分隔内容。文件末尾独立存在的内容仍保留为单独单元，避免在 diff 中丢失。

顶层匹配承担两个职责：

1. 建立两个版本之间的声明身份对应关系。
2. 决定后续 diff 应逐声明比较，还是把文件作为整体比较。

它不负责判断声明内部有哪些细粒度变化；这部分由后续的结构或文本 diff 完成。

## 指导原则

### 身份先于相似度

能够直接表达身份的证据，优先于视觉或结构上的相似。稳定身份标记强于声明名字；声明的语义角色又强于仅仅相似的函数体。

这种顺序可以防止一个“看起来很像”的新声明抢走另一个身份已经明确的声明的对应项。

### 强匹配成为锚点

一旦通过强证据建立对应关系，它就成为锚点。后续启发式匹配可以借助锚点理解局部上下文，但不能推翻锚点。

锚点会把文件划分为若干区域。只有当旧、新候选在周围锚点之间处于同一区域时，才允许进行启发式比较。这样可以避免把跨越已知声明的移动误判为原地重命名。

### 有歧义就不匹配

存在一个看似合理的候选并不充分。启发式匹配要求双方互相明确偏好：旧声明最偏好这个新声明，同时新声明也最偏好这个旧声明。

相似度并列时不会用源码顺序强行打破平局。若两个候选同样可信，就保留为删除和插入。

### 确定性优先于全局最优

匹配器使用分阶段的证据层级，而不是求解一次全局最优化问题。每一阶段只处理尚未匹配的声明，且更早、更强的证据拥有更高优先级。

这种方式让结果更稳定、更容易解释。插入一个无关声明，不应导致已经建立的其他配对被任意重排。

### 可控降级

顶层匹配只是细粒度 diff 的辅助信息，不是生成结果的前提。解析失败、计算成本过高或完全找不到可靠配对时，系统会扩大比较范围。

降级后的结果可能不够精细，但必须完整，也不能隐藏真实的文本变化。

## 证据层级

整体策略按照从强到弱的顺序使用证据。

### 显式身份

部分声明携带稳定的身份元数据。当这种元数据在文件中一致可用时，即使声明发生移动或内容大幅修改，它仍具有最高权威性。

重复身份按出现顺序确定地处理。当身份元数据只覆盖部分声明时，已经建立的对应关系成为锚点，其余声明继续进入后续阶段。

如果用户选择忽略注释，那么依赖注释存在的身份元数据也必须一并忽略，否则一条本应被忽略的注释会暗中改变声明身份。

### 语义身份

缺少显式身份时，声明按照语义角色进行比较。相关信息包括声明类别、声明名字、接收者、trait 上下文以及类似的所有权边界。

语义身份不依赖物理行号，因此可以处理常见的插入、删除和重排。同一语义身份重复出现时，按照出现顺序确定配对，而不会根据函数体相似度猜测重排。

### 精确结构身份

仍未匹配的单元，如果完整结构指纹在两边完全相同且各自唯一，就可以建立配对。这适合没有语义身份的匿名内容，也适合识别纯移动。

唯一性非常重要。相同结构出现多次时，指纹只能证明这些内容等价，无法证明具体 occurrence 之间的对应关系，因此这一阶段不会选择任意配对。

### 受约束的模糊相似度

最后一种证据是模糊相似度，它综合两个方面：

- 结构连续性：声明的大部分语法形状保持不变。
- 名字连续性：旧、新名字彼此相似。

概念上，声明名字与其余结构分开处理，使重命名不会摧毁结构相似度，同时名字接近程度仍可提供辅助证据。

模糊匹配受到声明类别和所有权边界的限制。方法不能漂移到另一个接收者；引用接收者方法不能仅凭函数体相似就与值接收者方法配对；不兼容的声明类别也不能成为候选。

它还受到锚点约束，会拒绝冲突的显式身份、拒绝平局，并且只接受双方互为唯一最佳的候选。完全没有可靠锚点时，不会仅凭模糊相似度凭空构造全局对应关系。

## 函数抽取中的连续性

当一个旧声明在新版本中被拆成两个声明时，会出现一种特殊歧义：

- 原名字保留为一个很小的 wrapper。
- 旧实现的大部分内容移动到一个新命名的 helper。

基于名字的语义身份更倾向 wrapper，而实现连续性更倾向 helper。只按名字配对，会让大量保留下来的函数体看起来像全新插入；只按函数体配对，又会丢失公开 wrapper 的身份连续性。

策略会非常保守地优先保留实现连续性，但只在重构形态十分明确时这样做：

- wrapper 在末尾直接委托给一个邻近 helper。
- helper 属于相同的声明上下文。
- 相比旧实现，wrapper 足够小。
- helper 明显且独特地保留了旧函数体的大部分内容。
- 没有其他旧声明同样可能是这个 helper 的来源。

函数体连续性关注旧计算结构有多少延续到了 helper 中，同时弱化注释变化、helper 改名等偶然差异的影响。

证据被接受时，旧声明与承载函数体的 helper 对齐，wrapper 则呈现为插入，并且不会在后续阶段重新参与匹配。这只是针对一种可明确识别的重构模式，并不是任意 split/merge 的通用模型。

只要任一证据较弱，例如 helper 不相邻、委托发生在条件分支中、所有权不一致、wrapper 仍保留大量旧函数体、存在多个竞争 helper，或存在多个可能的旧来源，就继续保留普通的语义身份配对。

## 从对应关系到 diff 计划

只要存在至少一个可信对应关系，就可以逐声明比较：

- 已配对声明彼此进行 diff。
- 未配对的旧声明视为删除。
- 未配对的新声明视为插入。

这样可以把声明内部变化与声明移动分离，同时在结果中保留原始源码位置。

如果一个可信对应关系也没有，匹配器不会强行绑定声明，而是把完整声明列表或整个文件一起比较。更大的比较范围保留了全局上下文，也让底层 diff 有机会自行发现有用结构。

纯重排需要特殊处理。结构视图可以合理地认为没有声明内部结构变化，因为每个声明本身都未改变；文本视图仍必须展示文件文本发生了变化，因此当逐声明比较会产生空结果时，需要降级为整文件展示。

## 资源边界

启发式工作量可能随未匹配声明的数量和大小快速增长，因此相似度计算必须受共享计算预算约束。

预算耗尽时，匹配停止并扩大 diff 范围，而不是返回一组不完整或不稳定的配对。

## 常见场景下的预期行为

| 场景 | 概念结果 |
| --- | --- |
| 在未变化声明之前插入一个新声明 | 既有声明保持身份，新声明显示为插入。 |
| 顶层声明重排 | 强身份跟随声明本身，而不是跟随原行号。 |
| 在稳定邻居旁重命名声明 | 可以在同一锚点区域内通过受约束的模糊相似度配对。 |
| 相似声明跨越稳定锚点移动 | 不猜测为重命名，保持删除和插入。 |
| 多个候选同样相似 | 不建立启发式配对。 |
| 相同匿名内容在两边各出现一次 | 可以通过精确结构身份配对。 |
| 相同匿名内容重复出现 | 在结构指纹阶段仍视为歧义。 |
| 大段函数体抽取到邻近 helper | helper 可以延续旧实现，wrapper 显示为插入。 |
| 解析失败或匹配超过资源限制 | 降级为整文件或完整列表比较。 |

## 有意保留的限制

这套策略有意不做以下事情：

- 不把相似度当作身份证明。
- 不跨越已建立的锚点边界进行启发式配对。
- 不用源码顺序掩盖相似度平局。
- 不猜测重复精确结构之间的 occurrence 对应关系。
- 不在弱证据出现后重新考虑强匹配。
- 不建立任意多对多声明 split/merge 模型。
- 不因精确匹配不可用而牺牲输出完整性。

这些限制倾向于产生可预期的 false negative，而不是更具误导性的 false positive。核心不变量很简单：每个已接受配对都应有清晰的身份解释，每个不确定情况都应继续显式保持不确定。
