# AST 行匹配与 Hunk 构造

[English version](./INTERNAL.md)

`ast_hunks` 包把语法级匹配位置转换为渲染 AST diff 所需的行级几何结构。AST 匹配器描述哪些源码 span 未变化、哪些发生变化；渲染器则需要有序的左右行、紧凑的变化区域和上下文窗口。这个包负责连接这两种表示。

它不判断语法节点身份，不计算行内高亮范围，也不构造最终 diff block。这些职责分别属于 AST 匹配器和外围 alignment 流程。

## 两种并行产物

这个包有意独立构造两种相关产物：

1. 供渲染使用的完整行配对表，由 `all_matched_lines_filled` 生成。
2. 稀疏的变化核心，由 `matched_pos_to_hunks` 生成。

完整表保留源码顺序以及没有语法位置的源码行，而 hunk 只记录涉及 novel 语法的行。之后，`contextual_index_range_for_hunk` 在完整表中定位稀疏核心并加入上下文。将两者分开，可以避免把上下文行和无语法位置的源码行误判为变化。

## 输入与坐标模型

左右两侧分别提供一组有序的 `MatchedPos`。每个位置包含一个单行源码 span，以及以下两种 kind 之一：

- `Unchanged` 携带一组对侧对应语法的 span；经过源码过滤后，这个数组也可能为空。
- `Novel` 表示该语法没有未变化的对应项。

输入 span 使用从一开始的行号。这个包对外暴露的行号都会转换为相对于调用方所传源码行数组的零基索引。在逐声明 diff 中，它们是声明局部索引，而不是整个文件的索引。

行配对 `(Int?, Int?)` 表示一个展示行：

| 配对 | 含义 |
| --- | --- |
| `(Some(lhs), Some(rhs))` | 在同一行展示两侧源码行。 |
| `(Some(lhs), None)` | 只展示左侧行。 |
| `(None, Some(rhs))` | 只展示右侧行。 |
| `(None, None)` | 非法，不会被有意生成。 |

双侧配对本身并不表示两行相等。它可能来自 unchanged 锚点，也可能来自仍保留部分 unchanged 语法的变化行，或为了展示而压缩得到的单行替换。消费方必须结合 novel 行集合和源码文本判断上下文与变化，不能只看配对形状。

## Hunk 表示

一个 `AstHunk` 包含三部分信息：

- `lines` 是稀疏、有序的变化核心，不包含上下文。
- `novel_lhs` 是该 hunk 中至少包含一个 novel span 的左侧行索引集合。
- `novel_rhs` 是右侧对应集合。

novel 集合区分左右两侧。一个双侧配对可能只有一侧是 novel；当某行保留一部分 unchanged token，同时增加或删除其他 token 时，这种情况很常见。

## 构造完整行配对表

### 保守选择 Unchanged 锚点

算法首先把所有 unchanged span 对应关系折叠为行到行的关系。同一行上的多个语法位置可能指向另一侧的多个位置，因此折叠结果可能存在歧义。

只有关系在两个方向都唯一时，才接受双侧锚点：当前行只指向一个对侧行，且该对侧行也只反向指向当前行。已接受的锚点在两侧还必须保持递增。因此，同一行上的重复位置以及交叉对应都不能产生重复或逆序的展示行。

算法不会猜测有歧义的多对多关系。相关行会在后续以单侧行形式插入，从而保留内容，又不声称存在缺乏依据的对应关系。

### 恢复所有可观察行

建立锚点后，算法会合并两侧所有被语法位置提及的行，再利用源码行数组恢复语法位置没有描述的行：

- 文件开头和结尾的行会在两侧都还有内容时按位置配对，多出的部分则作为单侧行。
- 紧邻双侧锚点之前的完全空行，会从后向前在两侧配对。
- 已观察行之间缺失的索引会作为单侧行插入，以保持每一侧连续。

最终结果在左右两侧各自保持有序：忽略 `None` 后，左侧已有索引递增，右侧已有索引也递增。这个表描述展示几何，因此不要求每一个展示行都具有语义锚点，也能保留完整 fragment。

### 只压缩最小替换 Gap

补齐连续行后，可能形成一段先是左侧单独行、随后是右侧单独行的序列。如果这一段在两侧恰好各有一行，就把它压缩为一个双侧配对，使简单的单行替换可以并排展示。

更大的 gap 仍保留为独立的左侧行和右侧行。若仅按位置强行配对，就会暗示一种 AST 从未提供证据的对应关系。

## 构造变化 Hunk 核心

### 收集 Novel 行并确定顺序

只要一行包含至少一个 `Novel` 位置，它就是变化行。Novel 位置没有直接的对侧 span，因此需要借助周围的 unchanged 位置推断其跨侧顺序。

在两个 unchanged 锚点之间的区域内，顺序是确定的：

1. 位于前一个锚点行上的 novel 位置最先。
2. 不具有 unchanged 行关系的行随后。
3. 依附于后一个锚点的位置最后。

如果一个变化行同时包含 unchanged 语法，算法可以使用下一个递增的对侧行关系，把两侧放在同一个展示行中。没有这类证据的行保持单侧。完成这一轮排序后，还会重新合并两侧的全部 novel 行集合，确保变化行不会仅仅因为缺少可用锚点而被遗漏。

### 强制单调递增

候选序列会被规范化，使每一侧都严格递增。如果某一坐标重复或向后移动，就把该坐标改为 `None`；只要可能，仍保留另一侧。只有两个坐标都消失时才丢弃整行。

这条规则优先保证序列稳定且可渲染，而不是保留可疑的双侧配对。

### 形成原始 Hunks

规范化后的变化行会被分组成原始 hunks。如果当前行的左侧坐标距离核心中最近的已有左侧坐标不超过四行，或者右侧坐标距离最近的已有右侧坐标不超过四行，它就继续归入当前 hunk；否则开始新的 hunk。

这个邻近性判断区分左右两侧：只要插入或删除在任一侧保持局部连续，即使另一侧行号跳跃较大，它们仍可位于同一个 hunk。随后，每个原始 hunk 只获得由其核心行实际表示的 novel 行集合。

## 定位上下文并合并 Hunks

Hunk 核心是稀疏的，但上下文来自完整行配对表。在定位核心之前，算法会补齐连续变化配对之间的行号区间，再查找完整表中触及任一侧核心行的第一项和最后一项。

`contextual_index_range_for_hunk` 按请求的半径扩展这个半开表索引区间，并限制在表边界内。半径计算的是匹配表中的展示行数，而不是两个源文件上彼此独立的物理距离。如果无法在表中定位核心，防御性结果是整个表，而不是空区间或截断区间。

`merge_adjacent_hunks` 使用 `context_lines + 1` 计算上下文窗口。窗口重叠或刚好相接的 hunks 会被合并，避免紧邻的渲染区域之间出现人为分隔。合并过程会：

- 合并两侧的 novel 行集合；
- 拼接变化核心；
- 分别去除左右两侧的重复行索引；
- 如果只有一侧重复，只把重复坐标替换为 `None`，保留另一侧不重复的坐标。

最后一条在两个重叠核心的某一侧提到同一行、另一侧却提到不同行时尤其重要。

## 与 Alignment 流程的集成

外围 alignment 包按以下顺序使用 `ast_hunks`：

1. 校验 AST 位置，并把它们映射到当前经过过滤的源码 view。
2. 调用 `all_matched_lines_filled` 构造渲染行表。
3. 调用 `matched_pos_to_hunks`，再调用 `merge_adjacent_hunks`，得到展示区域。
4. 对每个区域调用 `contextual_index_range_for_hunk`，并切出对应行表片段。
5. 结合 novel 行集合和源码文本精确相等性，对上下文行与变化行进行分类；原始 novel span 则用于行内高亮。

越界位置处理和 lexical fallback 发生在这个包之前或外围。`ast_hunks` 假定输入的位置流与源码数组已经处于同一个局部坐标空间。

## 常见场景下的预期行为

| 场景 | 概念结果 |
| --- | --- |
| 某行新增 token，但仍保留 unchanged token | 新旧行可以共用一个展示行；只有包含 novel span 的一侧被标为 novel。 |
| 同一行的多个 unchanged 位置都指向同一个对侧行 | 去重后的一对一行关系仍可成为锚点。 |
| 一行映射到多个对侧行 | 不为该关系建立 unchanged 锚点。 |
| Unchanged 关系会发生交叉 | 丢弃后续非递增坐标，而不是重排展示顺序。 |
| 匹配语法之前紧邻完全空行 | 从后向前配对这些空行，作为稳定上下文。 |
| 一个 gap 的两侧各有一个无锚点行 | 将两行压缩成一个可视化单行替换。 |
| 任一侧存在多个无锚点行 | 保持单侧展示，不进行推测性配对。 |
| 变化行在任一侧相距不超过四行 | 保留在同一个原始 hunk 中。 |
| 不同原始 hunks 的上下文窗口重叠 | 合并为一个渲染区域，且不重复行号。 |

## 有意保留的限制

这个包有意不做以下事情：

- 不运行文本 LCS 或相似度匹配来创造额外的行对应关系。
- 不把双侧展示行当作文本未变化的证明。
- 不在有歧义的多对多 unchanged 关系中任意选择。
- 不以破坏单调输出为代价保留交叉或重复坐标。
- 不在缺少 AST 证据时逐行配对较大的替换块。
- 不在匹配前置空行时把仅含空白字符的行当作完全空行。
- 不让四行的原始 hunk 阈值随调用方的 context 设置变化。
- 不校验 span、不决定 fallback 策略，也不把局部索引转换回整个文件的坐标。

核心不变量是：每个作为双侧语义锚点保留的源码行，都必须拥有明确、无歧义且保持递增的身份依据。其他内容仍然可以显示，但只能采用较弱的可视化配对或单侧行表示。
